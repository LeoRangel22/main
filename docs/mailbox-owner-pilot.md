# Restricted owner pilot for proposal replies

The existing read-only Mail connection and immutable reply routes remain the foundation. This adds the missing owner action surface; it does not enable public capture or send a proposal. Installation creates a closed control and an empty private polling ledger. No credential, consent, schedule, mailbox query, lead, payment or reservation is created by the migration or publication.

The existing Master session opens `piloto-respostas.html`. Status performs authenticated internal checks and a fixed `dryRun:true` call to the sender, never provider transport. It reports the effective lead-alert recipient and the two existing lifecycle hooks. One completed partial lead can generate two alerts, each to one configured recipient, with no CC/BCC in the deployed notification path. This is configuration/topology evidence, not delivery proof. An unknown destination or unexpected hook topology does not authorize new QA leads.

The page only admits one or two proposals labelled `[TESTE SEM VALOR COMERCIAL] QA-VENDA-01/02/03`, addressed to the current owner, without a booked agreement or payment. An accepted, uncertain or pending email cannot open a new send pilot. The recipient cannot be overridden by the page or API. The existing proposal review, revision and send ledger remain mandatory.

Opening sets a fixed fifteen-minute routing window; capture stays off. The operator reviews and sends through the normal Events proposal flow, once. Capture may then admit only one or two accepted send IDs with an immutable, unrevoked route bound to the same account, owner destination, proposal, reviewed revision and attempt. It has a four-message limit and a forward-only cursor starting no earlier than this window.

While this page stays open after explicit capture activation, it polls every minute. Each polling request has a durable UUID. Repeated or delayed request IDs never create another job; a distinct cycle requires a completed prior result and at least forty-five seconds. Unknown HTTP results stop new polling. The private job key stays in SQL and is never returned. The existing worker checks scope again before reading a body and before atomic commit; unrelated metadata cannot authorize a body read. Imported text cannot approve commercial terms or finances.

Evidence shown as persisted is joined back to the actual inbound event, send, proposal and immutable reviewed revision. It excludes manually reviewed neutral receipts. Reopening the proposal is still an operational test. Synthetic fixture receipts are never production homologation.

Explicit close disables only the matching pilot capture configuration and revokes only routes created for its selected proposals during this window. It preserves sends, messages, receipts and polling history. It rejects a changed capture scope instead of overwriting another operator. The fixed expiry blocks routing and mailbox work even if the browser closes. Physical flags must still be read back and closed; do not describe an expired-but-not-cleaned window as verified OFF. A page that opened the window attempts closure on expiry while its confirmed state remains available. An uncertain write stops automation and requires status/closure, never replay.

Deploy the additive migration first, then the reviewed sender and owner controller, then the static artifact. Read back all source bytes and inactive controls. A sender compatibility marker prevents the new controller from opening or capturing against an old sender. It is a compatibility check; deployment hashes provide the independent artifact identity. Existing environment-based public/legacy routing is not activated; it cannot coexist with an owner pilot for the selected proposal.

For rollback, close/read back the matching window before restoring sender/static source. Preserve the additive private tables, receipts and jobs. Restoration is not permission to drop history, replay a send, bypass authentication or import responses by subject/name. General public capture, bank confirmation and WhatsApp require their own verified journeys. The pilot alone is not public release approval.
