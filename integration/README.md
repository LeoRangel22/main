# Isolated sales and mailbox integration

Run `npm run test:db`, then `npm run test:integration`, with `TEST_DATABASE_URL`
pointing to the disposable PostgreSQL service on loopback. The integration adapter
rejects remote hosts and databases other than `postgres` / `events_test`, and uses
only `events_test`. PostgreSQL 17 and Chromium are used in CI.

`adjustment-persistence.spec.cjs` starts with an actual 30-person sent V1 and an
adjustment recorded by the anonymous public-response RPC. It uses the shipped
“Duplicar e ajustar”, review and save controls to change only the guest count to
32. The save goes through the real authenticated `save_event_proposal` function.
Version numbers are generated by PostgreSQL, never supplied by the test adapter.
Assertions cover the R$1,848 -> R$1,971.20 calculation, unchanged V1 content and
response, exactly one V2 after rapid repeat activation, stale-request refusal,
no outbox / reservation, a committed reread through a second connection, and the
application's history reload and editor reopening.

`mailbox-persistence.spec.cjs` executes the actual mailbox worker and its imported
TypeScript helpers. Only provider HTTP responses and local OAuth strings are
fictional; no external network is available. Real SQL prepares and binds the
reply routes to synthetic accepted sends, resolves the received headers,
deduplicates and atomically commits messages, receipts and cursor. Tests verify
the sent revision rather than the later current technical revision, a late V1
reply after V2, repeated scans, a provider alias for the same RFC Message-ID,
unrelated sender, missing threading, and missing mandatory Message-ID. Unsafe
messages have no body read; malformed headers do not consume the cursor. A new
database connection verifies committed message / receipt identity. Local capture
controls are switched OFF before the fixture commit.

Fixture rows may be committed **only in this disposable database** to test
durability; the next `test:db` run / CI service teardown discards the database.
The browser blocks external requests. These tests do not contact ZeptoMail or
Zoho, deploy functions, enable production capture, send email, register payment
or reserve an event. Passing them does not establish the cause of a production
message omitted by the Zoho API scan, nor does it replace live homologation.
